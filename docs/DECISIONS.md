# Decisions (choice, alternative rejected, why)

- One engine, two modes (dementia, autism): rejected two separate apps. Same need (decoding distress in people who cannot say what they need), one codebase, bigger story.
- Statistics find patterns, Claude explains: rejected letting the model find patterns. Deterministic counts cannot hallucinate, are cheaper, and are auditable.
- Controlled vocabulary in the formatter: rejected free-text tags. Consistent fields make counting and cross-family matching possible.
- Precomputed strategy scores from seed data: rejected live recomputation. One build day; live tracking is roadmap.
- Browser Web Speech API: rejected a paid speech vendor. Free, no keys, good enough for a demo with a headset mic.
- SQLite via Prisma: rejected hosted Postgres for the demo. Zero setup; swap later.
- Synthetic data only: rejected any real data. Health and children's data carry privacy law obligations we will not take on this weekend.
- Primary users are family caregivers at home (adult children of a parent with dementia, parents of autistic children): rejected nursing home aides as the lead user. Families are the team's chosen user, log on their own phones, and multiple family members plus a home aide create the same "nobody sees the whole day" problem.
- Full PRD scope with both modes live (PM, Nov 14): rejected the 3-feature cut and a single lead mode. The team wants Ask AI and the "one engine, two communities" story shown live; the cut list in TASKS is the fallback if behind.
- Reset demo data via POST /api/reset that re-runs the seed: rejected a manual redeploy. Judges type their own notes, so the demo needs a one-tap way back to the seeded state.
- Invitation-only entry via shared invite codes and a cookie (PM, Nov 14): rejected open access and rejected full accounts. Trust matters for families sharing sensitive notes; accounts are too much for one day. Judges get a code in the README so the public URL gate still passes.
- Intake profile asks age band, optional gender, spectrum level (mild, medium, severe), and communication level (PM, Nov 14): rejected a diagnosis field and a medication field. Research (docs/research/autism_patterns_by_age_gender.md) recommended support-needs wording instead of mild, medium, severe; the PM chose the plainer labels caregivers already use. Gender is for bias audits and display only.
- Expanded journey (PM, Nov 14): match and next step right after Save, caregiver check-in, "Did this help?" feedback, language picker, journal and overview are in; caregiver-to-caregiver messaging is roadmap only. Rejected building messaging now: free text between families is the main route for spam and unsafe advice, and it needs moderation we cannot build this weekend.
- Feedback counts are shown next to the score, not folded into it: rejected "more upvotes, higher score". Votes are easy to game and are not outcome evidence; the score stays tied to before and after logs.
- Two switches instead of one (Nov 14): `USE_MOCKS=false` turns on real AI for /api/log and /api/checkin; data routes stay on the in-memory demo store until `USE_REAL_DATA=true`. Rejected one switch for everything: the Prisma-backed data routes are not built, so one switch would have made every screen return 501 the moment real AI went live.
- Deterministic safety screen runs before any model call, with fixed wording, and the red flags are the union of the screen and the model: rejected trusting the model alone. Crisis handling must hold when the model is slow, down, or manipulated.
- Rules-only fallback when the model fails (keyword formatter, everything marked for review): rejected showing an error. A caregiver in a hard moment still gets a draft to confirm.
- Per-step results on what was tried (`responses`, contracts v5): rejected one outcome for the whole event. A real parent's note showed several things tried in order with different results; crediting the final calm to all of them corrupts the "what worked" statistics.
- A reported remedy is recorded as given (`remedy_given`) with no name and no result, and is excluded from statistics: rejected both dropping it and treating the report as a medication question. Parents report what they did; the app must not scold them, and must not measure or rank medicines.
- Self-directed biting and hitting are their own behaviors and always raise the self-injury flag: rejected one "biting" tag. The keyword fallback had logged a child biting her own hand as aggression.
- Formatter time limit raised from 9 to 18 seconds, client limit to 30: rejected keeping the "under 5 seconds" target for every note. Real spoken notes are about 150 words and took about 9 seconds, so most fell back to keyword rules.
- Renamed CareSignal to Unspoken: rejected keeping the name. CareSignal is an existing healthcare company (remote patient monitoring, part of Lightbeam Health Solutions), which is a conflict in front of investors and care programs.
- Each person has their own caregivers (contracts v6): rejected one caregiver list per mode. A tester adding a new person saw another family's names under "Who is logging?".
- Saved state in Postgres as one JSON snapshot per app (`STATE_DATABASE_URL`, `STATE_KEY`), loaded at server start and written after each change: rejected waiting for full Prisma-backed tables, and rejected a post-deploy copy script. It keeps what caregivers add across deploys today with a small, reversible change; real tables replace it later. Seeded demo data is rebuilt on each start so its dates stay current.
- No vector database for now: rejected adding one this weekend. Nothing in the product does similarity search; patterns are counts over a fixed vocabulary. If semantic search over notes is needed later, pgvector in the same Postgres avoids a second database.
- Seeded demo patterns are grounded in published findings and documented in `docs/research/seeded_patterns_sources.md`: rejected inventing patterns freely and rejected using any real log data. No public dataset of caregiver logs exists that we could use, and real logs would break the synthetic-data rule. New strategy scores come from the SCORING formula.
